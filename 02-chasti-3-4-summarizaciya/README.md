# Главы 3-4: MapReduce vs Refine - материалы и воспроизведение

Материалы статьи цикла «Суммаризация: MapReduce против Refine на живом замере».

## Что здесь

| Файл | Что это |
|---|---|
| `mapreduce.py` | Generic-скрипт стратегии MapReduce: split → map (саммари каждого чанка) → reduce (склейка) |
| `refine.py` | Generic-скрипт стратегии Refine: черновик живёт через всю серию шагов |
| `experiment-results.json` | Результаты живого замера из статьи (MapReduce 151с/15 вызовов, Refine 282с/14 вызовов) |
| `exp-mapreduce-vs-refine.py` | Оригинальный скрипт замера (обе стратегии в одном файле) |
| `materials/` | Схемы статьи + интерактивная HTML-версия |

Оба скрипта провайдеро-независимые: любой OpenAI-совместимый эндпоинт
(LM Studio, Ollama, vLLM, OpenRouter - что угодно с `/chat/completions`).

## Воспроизведение замера

Нужен: python 3.10+ (только stdlib), локальный или удалённый LLM-эндпоинт.

### 1. Подготовить вход

Любой длинный документ. В замере статьи: 10 разделов книги AI Agents and
Applications (~83 тыс. символов, 14 чанков по 6000).

### 2. Запустить обе стратегии на одном входе

```bash
# MapReduce
python mapreduce.py --input doc.txt --model <модель> \
    --base-url http://localhost:1234/v1 --chunk 6000 --out summary_mapreduce.txt

# Refine, наивный вариант (как в книге)
python refine.py --input doc.txt --model <модель> \
    --base-url http://localhost:1234/v1 --chunk 6000 --out summary_refine.txt

# Refine, смягчение recency bias: черновик как нумерованный список тем
python refine.py --input doc.txt --model <модель> --structured \
    --base-url http://localhost:1234/v1 --out summary_refine_structured.txt
```

### 3. Проверить главный тезис статьи

Наивный refine (без `--structured`) на документе с разнородными главами
скатывается к recency bias: итоговое саммари помнит конец документа и
теряет начало. Проверка:

1. Прогони refine без `--structured`.
2. Сравни итог с оглавлением входного документа: какие ранние темы исчезли?
3. Прогони с `--structured` и сравни полноту.

Условия замера из статьи: yandexgpt-5-lite-8b-instruct, LM Studio на RTX 4060,
temperature 0.2, задача - саммари «как выбирать модель и программировать промпты».

## Ожидаемые результаты (из замера статьи)

| Метрика | MapReduce | Refine (наивный) |
|---|---|---|
| Время (14 чанков, 8B модель) | 151 с | 282 с |
| Вызовов LLM | N+1 | N |
| Полнота по началу документа | широкая, обобщённая | теряется (recency bias) |

Refine даёт больше времени на каждом шаге (черновик растёт и перечитывается),
но при наивной реализации не даёт обещанной книгой полноты.

## Замечание для агентов, воспроизводящих эксперимент

- Метрика «полнота по началу» в статье оценочная (сравнение с оглавлением),
  не автоматическая. При воспроизведении можно автоматизировать: список тем
  входного документа vs темы в итоговом саммари, пересечение по эмбеддингам.
- `--structured` в refine.py - первая линия защиты от recency bias, не панацея:
  модель всё ещё может переформулировать существующие пункты. Для строгого
  эксперимента добавь diff-проверку «существующие пункты не изменились».
- Экономика: считай вызовы и токены. В MapReduce вызовов N+1 (каждый чанк +
  reduce), в Refine ровно N, но каждый последующий длиннее предыдущего.
